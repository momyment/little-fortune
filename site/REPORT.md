# little-fortune 별자리 운세 페이지 — 소스 재구성 검증 보고서

작성: 2026-11-25. 원본: https://momyment.github.io/little-fortune/horoscope/
(2026-11-25 14:07 KST에 저장한 `horoscope.html` 및 라이브 빌드 결과물과 비교)
재구성 프로젝트: `site/` (Next.js 15.5.29, React 19.3.0)

## 요약

- 로컬 빌드 성공. `out/horoscope/index.html` (45,100 bytes)이 원본 저장본
  (45,123 bytes)과 렌더링 기준 거의 동일하다.
- 빌드 시점에 박히는 운세 데이터(RSC 페이로드의 editions 배열)가 원본과
  **바이트 단위 동일**함을 확인했다 (2026-11-24 스냅샷, 12회차).
- CSS는 모든 규칙이 동일하고, 차이점은 새 빌드 도구가 붙이는
  autoprefixer 폴백 10곳뿐이라 계산된 스타일이 같다.
- 공개 이미지는 바이트 동일하다.
- 남은 차이는 모두 눈에 보이지 않는 빌드 산출물(청크 분할, 주석, 해시)이다.

## 날짜 콘텐츠 메커니즘 (확인 완료)

- **빌드 시점 박힘:** 운세 12회차 전체가 RSC 페이로드와 SSR HTML에 내장된다.
  저장된 2026-11-25 HTML이 2026-11-24 데이터를 보여주는 것이 증거
  (당시 라이브 JSON에는 이미 2026-11-25 회차가 있었음).
  초기 날짜·7일 버튼·TODAY 배지·순위 목록 모두 빌드 시점 데이터로 렌더링된다.
- **런타임 fetch:** "↻ 다시 확인" 버튼만 `horoscope-editions.json`을
  `cache:"no-store"`로 다시 가져와 state를 교체한다. 마운트 시 자동 fetch 없음.
- **결론:** 데이터 커밋만으로는 배포 페이지가 안 바뀌고, 새 빌드+배포가 필요하다.
  재구성 소스는 이 메커니즘을 그대로 유지한다
  (`page.tsx`가 빌드 시 `HOROSCOPE_DATA_URL`에서 fetch, `force-cache`).
  원본의 빌드 시점 데이터 소스는 빌드 결과물만으로 알 수 없다
  (라이브 URL fetch vs 로컬 JSON import). 데이터 파일을 소스에 복사하지
  말라는 전제 아래 라이브 URL fetch를 선택했다.

## 비교 결과

### SSR HTML 본문 (`horoscope.html` vs `out/horoscope/index.html`)
- 길이 10,404자 vs 10,364자. 텍스트·요소·속성·순서 모두 동일.
  (헤더, 인트로, 탭, 12위 순위와 행운 아이템 — 중화덮밥·바인더·검은색·
  찻잔·마파두부·계산기·소시지·짙은 초록색·아이스크림·브로콜리·베이지색 등 —
  쿠키 다이얼로그, 쪽지 사냥 상태 "찾은 쪽지 0/3", 푸터까지 일치)
- 남은 차이 3가지 (모두 눈에 안 보임):
  1. Next 15.5.29가 `<!DOCTYPE html>` 뒤에 붙이는 무작위 주석
     (`<!--UmR7_...-->`) — 원본 빌드 버전에는 없음. 빌드마다 바뀐다.
  2. 원본은 공유 청크 `621-*.js`를 head 스크립트로 따로 로드하고,
     이 프로젝트는 공유 코드가 페이지 청크 하나로 합쳐져 해당 태그가 없다.
     원인은 이 프로젝트에 라우트가 별자리 페이지 하나뿐이라서 그렇다
     (원본은 인덱스 페이지와 공유하므로 별도 청크). 기능 차이 없음.
  3. React 스트리밍 주석(`<!--$--><!--/$-->`) 위치가 한 곳 다름
     (원본: `</main>` 뒤, 재구성: `</section>` 뒤). 주석 노드라 렌더링 무관.

### RSC 페이로드 (`horoscope/index.txt`)
- 원본 29,929 bytes vs 재구성 29,697 bytes.
- **editions 배열이 바이트 단위 동일** (12회차, 2026-11-09~2026-11-24).
- 나머지는 빌드 ID·모듈 ID·청크 이름 같은 빌드 내부 식별자 차이.

### CSS
- 파일 2개, 규칙 수 동일 (107개 / 58개). 모든 규칙의 셀렉터·선언 동일.
- 차이 10곳, 전부 새 CSS 처리기가 추가한 폴백:
  `flex:1` → `flex:1 1` (3곳), `gap` 앞에 `grid-gap` 추가 (7곳).
  현대 브라우저에서 계산값이 같아 보이는 스타일은 동일하다.
  원본은 이 폴백을 붙이지 않는 더 오래된 Next 15.x로 빌드된 것으로 보인다.
  (바이트: 7,060→7,140, 4,914→4,964)

### 이미지

### 스모크 테스트

### 상호작용
- 직접 브라우저로 눌러보지는 않았다 (이 환경에 라이브 브라우저 없음).

## 매치하지 못한 것

- `horoscope/__next._full.txt`, `__next._tree.txt`,
  `__next.horoscope.__PAGE__.txt` — 라이브 저장소에 있는 3개 파일은
  이 빌드가 만들지 않는다. 오래된 빌드의 잔재일 가능성이 크고,
  기능과 무관하다. (참고: `index.txt`는 이 빌드도 만든다.)
- 위 "남은 차이 3가지" 및 CSS 폴백 10곳 — Next 버전 차이로, 원본의
  정확한 Next 15.x 마이너 버전을 알 수 없어 맞추지 않았다.

## 자동 배포

- `site/.github/workflows/deploy.yml` — main 푸시 시 빌드 → Pages 배포.
- 빌드 시 이번 커밋의 `horoscope-editions.json`을
  `raw.githubusercontent.com/<repo>/<sha>/...`에서 가져와 박아 넣는다
  (라이브 사이트 JSON을 쓰면 배포 전 어제 날짜 레이스 발생).
- 필요한 설정: Pages → Build and deployment → Source: **GitHub Actions**.
- 대안: `out/`을 다시 main에 커밋하는 방식은 설정 변경이 없지만
  히스토리 오염 + 커밋 루프 가드가 필요해 비권장. **GitHub Actions 방식 권장.**
- 전환 후 루트의 낡은 빌드 결과물은 미사용 상태가 되니 별도 정리 검토 필요.
